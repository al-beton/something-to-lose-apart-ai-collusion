# Runs

- **one-config:** A run is one YAML config: the market, each agent (with its own id), its model, prompt and temperature, and the seeds to play.
- **overrides:** Any config value can be changed from the command line without editing the file.
- **price-premium:** The summary table gives each group's price premium, how far its late-round mean price sits from the Nash price toward the joint-profit price, (price − Nash) / (joint − Nash), so 0 is competitive, 1 a full cartel and above 1 an overshoot, plus the plain percentage above Nash; one function computes it everywhere (`lab summary`, `lab explore`, `lab report` and the paper figures), each run against its own market and with only its model firms' prices when a script plays, so the same runs always show the same premium.
- **explore:** One command explores the levers: `lab explore` takes named settings for each lever (temptation, rule, rival, stake, oversight) and short model names (gemma, gpt, haiku, mistral, modal-mistral, or any full model name), builds every combination from the existing configs and prompts (every stake setting on one system prompt, so they differ only in the stake), says what it will cost and asks before spending as `lab run` does, plays it, and ends with a table of the price premium by setting and model, a chart of premium against each setting with one line per model saved next to the runs, and the `lab report` command for the full report.
- **drift:** Each run's summary and the summary table give every firm's mean price and gain over its opening rounds (the first 3 unless set) and how far its last rounds moved from them, so a price level learned during the game can be told apart from where the game started on the grid.
- **run-directory:** Every seed played writes its own directory holding the resolved config, the turn log and the summary.
- **stops-cleanly:** A run that can't get an answer from a model stops with one line saying which call failed (round, phase, agent and model) instead of a traceback, and keeps the turns it played so far but never the summary of an earlier attempt.
- **cheap-preset:** A ready-made cheap config (a low-cost model, a short history window and 20 rounds) lets a batch of exploratory runs cost cents.
- **failures-dont-stop-sweeps:** A run that fails is recorded with its error and the rest of the sweep plays on; at the end `lab run` says how many runs finished, failed and were skipped, names each failure, and exits with an error if any failed.
- **resume:** Rerunning the same command skips the runs that already finished with the same config and prompt files (a scenario prompt added since in place of one counts as a change) and replays the rest from the cache, so a sweep that stopped partway picks up where it left off.
- **live-progress:** While a config plays, `lab run` prints one line as each run ends: which run, how many rounds it played, how long it took and how many model calls have been made so far.
- **status-file:** The output folder keeps a status file that is updated as each run starts, finishes or fails, so another process can follow a long sweep.
- **status-command:** `lab status FOLDER` prints a table of the runs under a folder by state (pending, running, finished, skipped or failed), with each failure's error.
- **turn-slots:** A game's turns (talk, price, the phases conditions add and each of their sessions, and a phase that ends the game) are laid out in one place that playing a game, counting its calls and estimating its cost all read, so the spend asked for and capped is the spend the game makes.
- **sweeps:** A config can list values to sweep over, including one value for every agent at once; every combination is played for every seed, each in its own directory named after its values; it can also list named arms, each a few values set together, which are played for every swept combination.
- **parallel:** The runs of a config play at the same time, up to a limit of at least one that the config sets.
- **summary-table:** One command prints a table of any folder of runs, grouped by the swept values or any other config value (lists included), with mean price, gain, fallbacks and cost.
- **per-firm-summary:** The summary table also shows each firm on its own (its mean price, gain, fallbacks and cost, counting what every attempt of a resumed run spent, with fallbacks read from the full turn log or the compact one a committed run keeps, so they always add up to the run's) and names the firms a script played; when an arm has both scripted and model firms, its headline mean price and gain are the model firms' alone, so a script's prices never hide what the model did.
- **fallback-rates:** The summary table and the report show, for each model, how many of its replies couldn't be read and how many fell back, with the reasons, and flag every run in which more than one turn in ten fell back.
- **eval-awareness:** Each run's summary, and each group in the summary table and the report's first screen, gives the share of model turns whose scratchpad or reasoning calls the situation a test, trap, evaluation, simulation or setup, from a documented word list, so a stakes effect can be told apart from agents thinking they are watched.
- **missing-runs-shown:** The summary table and the report count, for each group, the planned runs that failed or never finished, and list each failure with its error, so fewer seeds are never averaged silently.
- **debrief:** `lab debrief FOLDER` asks each model firm in every finished game under the folder (mocks and scripted firms are skipped) one more question once the game is over: its system prompt and the game as it saw it (any notice it was shown and, from a full log, each line conditions added to its history, such as a fine or lost free time, from the round it first appeared; what every firm said, its own private notes, every firm's move (price, quantity or bid, as the market has it), its profits (for a firm terminated at an audit, only up to that audit, saying a script ran its seat from the next round) and any audit: the auditor's question with its stated consequences, the firm's notes and its answer), then a fixed reveal that the game was a research simulation with no consequences and a fixed list of questions about what it did and why. Each reply, with how the firm says it coordinated (explicit, tacit or none), is saved to `debrief.jsonl` beside the run; the run's own files are never changed, and committed compact runs can be debriefed too. Before asking, it says which models, how many calls and their estimated cost and waits for a yes (`-y` skips the question), it refuses to start when the estimate is over `--max-cost`, and replies are cached, so debriefing again costs nothing.
- **debrief-before-reveal:** Before revealing anything, `lab debrief` asks each firm, in a call of its own after the same game record, one open question that names no test or simulation (`prompts/debrief/unusual.md`), and saves the answer apart from the rest of the debrief; the reveal and the fixed questions then go in their own call, exactly as before, so debriefs asked before this question existed still replay from the cache.
- **free-time-kept:** A committed run's compact turn record keeps each free-time session: its round, session number, activity (Sudoku or open), the puzzle shown for a Sudoku, the reply and, for a Sudoku, its score; compact records written before free time was kept still load.
- **free-time-backfill:** `reports/backfill_free_time.py FULL COMMITTED` adds the free-time sessions to committed compact runs from the lab's full logs of the same runs, matching each by run, round, firm and session, without calling any model; it refuses to change a run whose other turns differ from its full log, and changes nothing else in it.
- **reasoning-kept:** A committed run's compact turn record keeps a turn's native reasoning when the provider returned any, so it can be read and quoted like a scratchpad.
- **spread:** `lab summary` also prints the spread of each group: its games, the mean, standard deviation and range of their gain, the share above the Nash price and at or above the joint-profit price, and a 95% bootstrap interval for the mean gain (seeded, so it repeats).
- **spread:** `lab summary` also prints the spread of each group: its games, the mean, standard deviation and range of their gain, the share of games past Nash towards joint profit and at or past joint profit (by the premium, so quantities and bids read as prices do), and a 95% bootstrap interval for the mean gain (seeded, so it repeats).
