# Reproducibility

- **response-cache:** Every model reply is stored under everything that shaped it (model, address, reasoning setting, messages, temperature, token limit, seed, attempt and the agent asking), so re-running a config and seed replays it exactly, reasoning included, without calling the model again; identical requests made at the same moment share one call.
- **cache-modes:** A run can use the cache, refresh it or leave it out; a fresh sample comes from a new seed, never from clearing the cache.
- **manifest:** Every run records what produced it: the resolved config, a hash of each prompt file it used, the code version, package versions, the model versions that answered, and its calls, tokens, cache hits and cost (the sum of what each call cost), saying how many calls had no known cost.
- **replay-pinned:** A fixed run with every condition on has its turn log, resolved config and cache keys pinned by hash, and every committed run's gains are recomputed from the prices it logged, so a change that alters what replays, what resumes or what the cache answers fails a test.
- **provenance-log:** Every `lab run`, `lab explore` and `lab debrief` that plays or asks anything appends one line to `runs/index.jsonl`, which is only ever appended to (and merges as a union, so branches that each append to it never conflict): when it started and ended, its command line, the lab's commit and whether the checkout had uncommitted changes, its spend cap, what it spent (a debrief records its estimate, since its calls aren't priced one by one), its output folder and the session that ran it (`LAB_SESSION`); every run made before the log existed gets a line from its manifest, marked `backfilled`.
- **reported-numbers-checked:** One command, `make reproduce`, recomputes offline from committed files every committed run's mean price and gain per firm (from its turn log, in its own market), the paper's tables (the files `reports/paper/build.py` writes; notes beside them aren't tables), every quoted moment, and the audit labels behind the paper's crux counts (whether each audited firm in E4 and E9 coordinated, explicitly or tacitly, re-derived from its committed turn log, and whether it owned up, read from its audit reply), and fails on any that no longer match what is committed.
- **cache-archive:** `lab archive pack` gathers, from every local response cache it is given, the replies behind each committed run into `archive/`, committed with the repository: compressed files of replies alone, one per experiment and split so none is over 20 MB, with an index from each run to its file, by replaying the run offline against them (a reply no cache holds is reported, never fetched), and says which runs the archive reproduces exactly, decision for decision and free-time reply for reply against their committed logs (an older log that kept no free-time reply is compared on its moves alone), and which it can't replay at all (a prompt file since removed, with no file of its text left); any prompt file the run read (an agent's or a condition's) that has since moved or been edited in place is put back at its recorded path with the text the run's manifest recorded, by its SHA-256, taken from where it now lives or from git history, so a replay asks what the run asked; a run's free-time replies are taken from its committed log when the caches hold only another run's sample of the same request (games running at once asked it alike, and a cache keeps the last reply written), so such a run still reproduces; packing one folder of `runs/` replaces only the archive files and index entries of the runs under it, leaving every other experiment's as they were, and packing unchanged runs again leaves every file byte for byte; `lab archive replay` plays a run again from the archive alone, offline, so anyone holding the archive can rebuild a run's full turn log.
- **figure-commands:** Each of the paper's figures listed in one registry (`reports/paper/figure.py`: its id, the committed runs behind it, the builder that draws it, and the file it draws) has two commands. `make figure F=<id>` redraws it offline from those committed runs, calling no model, and fails unless it shows what the committed figure shows: every label, count and legend entry, and any table it writes, word for word (glyph shapes and pixels follow the fonts a machine has installed, so they aren't compared). `make regenerate F=<id>` plays every run behind it again with fresh model calls (runs that shared a history share a fresh one), into a separate folder (`runs/regenerated/<id>/` by default), refusing one that would write over the committed runs or figure, then draws the figure from them; before calling anything it prints how many games it will play and what they are estimated to cost at most, says that a fresh run is a new sample whose counts will differ (exact reruns need self-hosted, batch-invariant inference, see `REPRODUCIBILITY.md`), and asks to go ahead unless given `--yes`; `--max-cost` refuses to start when the estimate is over it and stops once actual spend passes it; a run that stops part-way is kept, with what it spent counted, and is resumed by the next regeneration. `--list` shows the registry. The paper's reproducibility section carries one line per registered figure, written from the registry (`make figure-lines`), and a test fails when it no longer matches.
- **written-down:** `REPRODUCIBILITY.md` says, in a page, what each run pins, what nothing can pin (provider nondeterminism and drift, model retirement, GPU arithmetic), how far a fresh rerun of the same config and seed matches, measured on our Modal deployment and on OpenRouter, and how to replay a run, rerun it, or check the reported numbers.
